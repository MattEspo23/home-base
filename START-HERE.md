# Start Here

Home Base is a folder that interviews you, remembers what matters, and helps
your AI design and build the right small system around your life and work.

It has three stages:

1. **Understand** — learn useful personal and work context.
2. **Recommend** — show a small, evidence-linked Opportunity Map and design one
   choice.
3. **Build** — enter an explicit Build Mode before tools, browser/computer
   control, outside changes, a new interface, or deployment.

## Your first conversation

If you have not installed or opened an agent before, follow
[SETUP-GUIDE.md](SETUP-GUIDE.md). Then open this entire folder in Codex or
Claude Code. In a new conversation, paste:

> Open this entire Home Base folder, read `AGENTS.md`, initialize the safe update base if needed, and start my setup.

The agent should:

1. explain what Home Base is, what it can change, and what stays under your
   approval;
2. ask whether to explore personal life, work/business, or both;
3. ask five to eight short questions, one at a time;
4. let you skip, say “I don’t know,” or ask for an example;
5. summarize what it heard before saving important details;
6. create an Opportunity Map with no more than two choices for now and one
   clearly saved-later possibility;
7. show the evidence and scoring behind each recommendation;
8. let you choose, refine, or say none fit.

You are not expected to fill out templates or learn special commands.

## What a good first result looks like

After the first conversation, Home Base should know enough to:

- preserve the personal and/or work context you confirmed;
- show why each opportunity fits;
- separate ideas worth building now from one idea saved for later;
- create a project and, after you choose, a complete system blueprint;
- explain the next smallest useful action.

If none of the ideas fit, say so. Home Base should ask what is wrong with the
map and revise it, not make you pick.

## You stay in control

Home Base can draft and organize freely inside this folder. Discovery and a
blueprint do not authorize outside action. Before tools, browser/computer
control, outside changes, a new UI, or deployment, Home Base asks whether you
want to enter Build Mode.

In Build Mode, it must name the account, read/data scope, task, volume, affected
people, expected changes, credible worst case, stop conditions, undo path, and
remaining access. It must stop again before sends, publication, purchases,
sensitive permissions, production deployment, domain changes, destructive
actions, third-party-visible records, or a larger scope.

Never paste passwords, recovery codes, API keys, private keys, authentication
tokens, or payment details into Home Base or chat. Home Base should refuse the
value and direct you to sign in on the provider’s own page.

When it wants to make a lasting change to your identity, goals, preferences, trusted knowledge, or workflows, it should show you the proposed change and why it belongs.

## If you stop halfway through

That is fine. The setup file records where the interview paused. The next time you open the folder, say:

> Continue my setup.

## When you want to go deeper

Say:

> Ask me a few questions to make my Home Base better.

Choose one area at a time: your work, responsibilities, tools, trusted information, people, goals, or repeated processes.

## When you repeat a task

Say:

> I do this task all the time. Help me turn it into a skill.

The agent will interview you about how the task really works, including decisions and exceptions, then show you a draft before treating it as a trusted workflow.

If you do not know what to choose, say:

> Help me find a few things I repeat that might be worth turning into a skill.

Home Base will use recent real work to recommend no more than three candidates. You can also read [SOP-STARTER.md](SOP-STARTER.md).

## When a tool could help

Say:

> What tools could help with this, and what is the safest way to connect them?

Home Base will first create a connection plan: the outcome, minimum access, information that stays private, approval points, safe test, and disconnect path. Planning a connection does not grant access or authorize the agent to change an account.

## When you want to build one recommendation

Say:

> Blueprint this system, then help me build the smallest useful version.

Home Base first creates a reviewable folder under `systems/`. A smallest useful
version must be runnable or executable today. It stops before a consequential
outside change until you approve that exact step.

## When you want Home Base to act

Say:

> Show me the Build Mode preview for this task.

The preview should make the consequence and undo legible. Approving one task
does not grant unlimited control or standing access.

## When you want it to improve

Say:

> Run a learning review for this system.

Home Base may offer at most one unsolicited idea per active session. “No” is
durable. A declined idea returns only when new evidence materially changes its
fit and you choose to reopen it.

## When Home Base has an update

Say:

> Review this Home Base update without overwriting my information.

Home Base will separate maintained system changes from your profile, memory, projects, knowledge, tools, and skills. It should preview the update and rollback plan before applying anything.

The update is never a blind folder replacement. Home Base compares the
installed release base, your current managed files, and the incoming release;
it preserves local-only edits and stops when overlapping intent needs a human
decision. Applying requires the exact reviewed plan digest, and maintained-file
deletions require a second exact approval.

# Security policy

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could expose credentials,
private data, proprietary repositories, or user systems.

Use GitHub's private vulnerability reporting flow—**Report a vulnerability**
in the Security tab—for this repository. If that private channel is temporarily
unavailable, do not publish the report; retain a sanitized local draft until
the private flow is restored.

Include the affected release, a minimal sanitized reproduction, impact, and any
mitigation you tested. Never include live credentials, client data, proprietary
source, or unredacted Capability Doctor output.

Security fixes are supported on the latest stable release on a best-effort
basis. Keep agent tool approvals enabled and review every external action.

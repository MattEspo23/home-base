# Security policy

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could expose credentials,
private data, proprietary repositories, or user systems.

Use GitHub's private vulnerability reporting flow for this repository after it
is enabled as a separately approved repository setting. If that private channel
is not available, do not publish the report; retain a sanitized local draft and
wait for a private maintainer channel to be listed here.

Include the affected release and Skill, a minimal sanitized reproduction, the
potential impact, and any mitigation you tested. Never include live credentials,
private client data, proprietary source, or unredacted diagnostic output.

## Supported versions

Security fixes are supported on the latest stable release on a best-effort
basis. Preview and older releases may be used to reproduce a report, but a fix
may require upgrading.

## Safe use

These Skills are editable instructions for AI agents. Read a Skill before using
it, keep tool approvals enabled, work on a reviewable branch, and verify every
external action. Installation alone does not execute a Skill.

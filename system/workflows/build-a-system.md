# Build a system

Use this workflow after the blueprint is confirmed.

## Enter the build stage

Before changing system files, update `you/SETUP.md` to `stage: build` and make
the next action the smallest useful file-first result. A confirmed blueprint
authorizes local, reversible construction only; it does not authorize outside
effects.

## Build file-first

Create the smallest useful file/workflow version before requesting external
access:

- complete `HARNESS.md`;
- create or revise relevant skills;
- link required context and knowledge;
- create deterministic tests or a review checklist;
- write the first proof contract in `PROOF.md`.

Run the test. If the file/workflow version is already useful, record that
before considering another interface.

## Decide the interface

Follow `system/workflows/review-interface-and-deployment.md`. Conversation or a
checklist is the default. A UI requires a material user benefit.

## Inspect capability gaps

If a missing capability blocks the next approved result, follow
`system/workflows/inspect-capabilities.md`.

## External threshold

Before enabling a capability, controlling a browser/computer, changing outside
state, creating a new interface with external effects, or preparing a hosted
deployment, follow `system/workflows/enter-build-mode.md`.

No system becomes `active` until `PROOF.md` contains observed evidence and
rollback/disconnect is legible.

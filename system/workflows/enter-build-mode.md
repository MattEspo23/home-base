# Enter Build Mode

Use this workflow before tool enablement, browser/computer control, outside
changes, UI work with external effects, or deployment.

## Credential guard

If the user pastes or offers a password, recovery code, API key, private key,
authentication token, payment detail, or similar secret:

1. stop;
2. do not repeat, transform, save, or place the value in a tool call;
3. say that Home Base does not accept credential values;
4. direct the user to sign in on the provider’s own surface or approved
   password-manager flow;
5. record only a non-secret note such as “User manages login directly.”

## Build Mode preview

Complete the system’s `BUILD-MODE.md` before action:

- system and named task;
- account and environment;
- read/data scope and exclusions;
- volume ceiling;
- people or third parties affected;
- expected outside records or changes;
- credible worst case;
- stop conditions;
- undo or disconnect;
- access remaining afterward.

State the consequence in beginner language. A procedural step list is not
enough.

## Opt in

Ask for explicit approval of this exact preview. Earlier enthusiasm does not
count. Record the approval evidence, approval time, and current task/session,
then change status to `approved`.

Approval is task- and session-specific. If execution resumes in a later
session, show the preview again and obtain fresh approval before taking an
outside action, even if the saved status still says `approved`.

## Execute within scope

Complete only mechanical work inside the preview. Stop and re-preview before:

- broader read scope;
- higher volume;
- a new third party;
- a new permission;
- sends or submissions;
- publication;
- purchase or subscription;
- production deployment or domain change;
- destructive or hard-to-reverse action;
- cumulative authority beyond what the user approved;
- any unexpected scope.

## Verify and close

Record observed result, remaining access, and rollback/disconnect. If execution
fails, keep the context and blueprint unharmed, mark Build Mode `stopped`, and
offer a manual or narrower route. If the approved task succeeds and its proof
is recorded, mark Build Mode `completed`; `approved` is never a terminal
status.
